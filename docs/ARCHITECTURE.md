# 구조

```
photo ──▶ EditRecipe(불변 상태) ──▶ PhotoProgram(GLES 3.0) ──▶ 프리뷰 / 원본 해상도 파일
              ▲                    ▲
              │                    └── LUT 17³ 3D 텍스처
   자연어 파서 ─ 로컬 LLM ─ 사진 분석(히스토그램) ─ 기울기 추정
                          │
                          └── NIMA(224px 오프스크린 렌더 → TFLite 채점) ──▶ 자동 보정 후보 탐색
```

## 1. 상태

- `core/Param.kt` — 파이프라인이 아는 모든 값의 이름·범위·기본값·표시 형식.
- `core/EditRecipe.kt` — 값을 `Map<Param, Float>`로 들고 있는 불변 레시피. `with`, `plus`, `apply`,
  `toJson/fromJson`. 기본값과 같은 항목은 JSON에 쓰지 않습니다.
- `core/RecipeDelta.kt` — 상태가 아니라 **변경 설명**. `Add`(상대)와 `Set`(목표) 두 가지.
  `Set`은 현재 값에서 목표로 강도만큼 보간하므로 "절반만 흑백" 같은 표현이 자연스럽습니다.
- `core/RecipeSession.kt` — 레시피 **레이어 스택**. 각 레이어(`EditStep`)는 자기가 바꾼 것만 들고
  있습니다: 말로 한 보정은 `RecipeDelta`(상대), 룩·슬라이더·자동은 그때 정한 절대값(`targets`).
  그래서 `remove(id)`가 가운데 단계를 빼고 나머지를 원본부터 다시 합산할 수 있습니다.
  undo/redo는 레이어 목록 스냅샷이라 잘못 지운 단계도 되살아납니다. 직전 단계 반복(`repeatLast`),
  강도 절반 재계산(`halveLast`). 최대 200단계 / 되돌리기 100회.

원본 `Bitmap`은 어디에서도 수정되지 않습니다. 프리뷰용 축소본과 저장용 원본을 따로 디코드하고,
둘 다 같은 레시피를 셰이더에 넘깁니다.

## 2. 렌더링

`gl/ShaderSource.kt`의 프래그먼트 셰이더 하나가 전부입니다.

```
uv → 기하(회전·내접 크롭·수직 원근) → 노출(linear) → 톤 → 색온도/틴트
   → 채도/활기 → 색 정돈(색상 수 감소) → 색 교차 → 섀도우/하이라이트 색 분리
   → 피부톤 정리 → 명료도/텍스처/샤프닝 → 디헤이즈 → 글로우/할레이션
   → 흑백 → 피사체 강조 → 3D LUT → 8색 HSL → 영역(피사체/배경/하늘) → 비네팅 → 그레인
```

- **8색 HSL**(`uHslActive`, `uBandHSL[8]`)은 LUT 뒤에 옵니다. 룩이 색을 한 번 접은 뒤에
  사용자가 고른 대역만 손대는 편이 "빨강만 살리고"의 결과가 예측 가능하기 때문입니다.
  대역 가중치는 `bandWeight()`의 코사인 창이고, 이웃 대역의 창이 서로 보완이라
  색상환 전체에서 가중치 합이 1입니다(`core/HslBands.kt`가 같은 식을 Kotlin으로 갖고 있고,
  단위 테스트가 둘을 맞춰 둡니다).
- **영역 보정**(`uMaskOn`, `sampler2D uMask`)은 텍스처의 R(피사체)·G(하늘)로 가중합니다.
  밝기는 linear light에서, 채도는 luma 혼합으로, 선명도/배경 흐림은 원본-블러 잔차로 적용됩니다.
  배경 흐림은 새 블러를 한 번 더 돌리지 않고 이미 계산한 `wide` 잔차를 덜어 내는 방식이라
  프리뷰에서도 비용이 거의 늘지 않습니다.
- `uMaskPreview`는 확인용 오버레이이고 저장 경로에서는 항상 0입니다.

- 지역 연산(명료도·텍스처·샤프닝·글로우·할레이션·피부톤)은 8탭 샘플로 계산하며,
  반경은 이미지 크기의 1/1000 단위라 **프리뷰와 원본 해상도 저장이 같은 세기**로 보입니다.
- `PhotoRenderer`는 화면 크기에 맞춰 letterbox 뷰포트를 잡고 `RENDERMODE_WHEN_DIRTY`로 필요할 때만 그립니다.
- 가로 비교(`uSplitEnabled`/`uSplitY`)는 프리뷰 전용입니다: 선 위는 보정 전, 아래는 보정 후 픽셀이고,
  Compose 오버레이가 같은 aspect-fit 계산으로 선·핸들·뱃지를 그 위에 얹습니다. 저장 경로는
  `splitEnabled = false`로 그려 전체 보정 이미지가 나옵니다.
- `OffscreenExporter`는 별도 EGL 컨텍스트 + FBO에 원본 크기로 그리고 `glReadPixels`로 읽어
  행을 뒤집어 `Bitmap`을 만듭니다. GL 최대 텍스처 크기를 넘는 사진은 자동 축소하고 그 사실을 알립니다.

## 2-1. 영역 마스크

`image/MaskGenerator.kt` + `image/MaskMath.kt`

1. 사진을 긴 변 1024px로 줄이고 픽셀을 읽습니다(프리뷰·저장 공통).
2. MediaPipe **ImageSegmenter**(`models/selfie_multiclass_256x256.tflite`, 번들 asset)를
   `RunningMode.IMAGE`로 돌려 **신뢰도 마스크 6장**을 받습니다. 클래스 0(배경)의 1−값이 피사체입니다.
   출력 컨테이너가 `VEC32F1`이면 `ByteBufferExtractor`, 비트맵이면 `BitmapExtractor`로 읽고,
   256px 출력을 사진 크기로 최근접 리샘플한 뒤 페더링합니다.
3. 하늘은 모델 밖에서 계산합니다(`MaskMath.skyMask`): 색(파랑~중성)·밝기·상단 위치·행 단위
   비율(행의 28% 이상이 하늘스러워야 인정)로 점수를 만들고, 피사체 마스크를 빼고, 페더링합니다.
4. 모델을 못 쓰면 `MaskMath.heuristicSubject`(테두리 평균색과의 거리 × 중앙 가중치)로 폴백합니다.
5. 결과는 ARGB 비트맵(R=피사체, G=하늘)으로 패킹되어 GL 텍스처 한 장이 됩니다.

`OffscreenExporter`는 저장할 때 원본 사진에서 **같은 생성기로 마스크를 다시 만들어** 씁니다.
마스크는 사진 좌표에 고정되어 있으므로, 기하 변환은 셰이더가 소스 UV를 계산할 때 마스크에도
같은 UV를 적용해 자동으로 따라갑니다.

## 3. 기울기

`geom/StraightenEstimator.kt`

1. 640px 이하로 박스 다운샘플 → 휘도
2. 3×3 이항 블러 → 중심 차분 기울기
3. 12px 블록(6px 간격)마다 `Σgx², Σgy², Σgxgy`
4. 주 방향 `φ = ½·atan2(2Σgxgy, Σgx²−Σgy²)`, 일관성 `coherence`
5. `φ mod 90`을 ±45°로 접어 0.1° 히스토그램에 `√energy × coherence` 가중 투표
6. 1.1빈 가우시안 스무딩 → 피크 → 포물선 보간

`geom/GeometryMath.kt`가 같은 변환을 Kotlin으로 구현해 테스트에서 소프트웨어로 되돌려 봅니다.

```
frame = (uv − 0.5) · (aspect, 1) / cropScale
src   = R(straighten) · frame           (y 아래 방향 좌표)
src.x *= 1 + verticalTilt · src.y · 0.45
uv'   = (src.x / aspect, src.y) + 0.5
```

## 4. 자연어

`nl/PromptEngine.kt`

- 프롬프트 한 줄이 세션에 하는 일(대화 제어 → 수평·수직 → 룩 의도 → 제한 → 영역·색상 → LUT)을
  **안드로이드·UI와 분리한 순수 코틀린**으로 모았습니다. `EditorViewModel.submitPrompt`는 이 결과를
  받아 상태만 옮기고, 그 사이 어디서든 난 예외는 카드 한 장으로 바뀝니다(앱은 계속 살아 있습니다).
- 이 분리 덕분에 폰에서 도는 그 코드를 `PromptSubmitTest`가 직접 돌립니다: 빠른 요청 칩 전부,
  파라미터 66개 각각의 서술/적용, 히스토리 중간 삭제와 되돌리기, **무작위 문장 4,000개**.
- `Result`는 "카드를 새로 쓸지/지울지/그대로 둘지"(`NoteAction`)와 스낵바 문구까지 정해서 돌려주므로,
  2.2.0까지 `submitPrompt` 안에 있던 판단이 한 곳에 모입니다.

`nl/NaturalLanguageParser.kt`

- 정규화(소문자·구두점 제거) 후 **긴 구절부터** 소비하며 매칭. 이미 소비된 구간은 다시 쓰지 않습니다.
- 순서: 대화 제어 → 수평·수직/각도 → 말버릇·수식어 → **부정·억제** → 룩 이름 → 룩 의도 → 남은 문장.
- 말버릇("그거 아시죠", "뭔가", "약간 그런")과 연결어("~하면서도")는 의도보다 먼저 지웁니다.
  수식어도 "남은 문장"에서는 빼되, 강도 계산(`modifierBefore`)에는 그대로 씁니다.
- 부정 표시(`~하지(는) 않`, `~지(는/지도) 않`, `~지 못`, `~하지 말`, `~는 말고`, `~은 빼고`,
  `~ 없이`)를 축으로 삼아, **바로 앞 6자 안의 말**만 그 표시에 딸린 것으로 봅니다. 그 말이
  `Restraints`(화려·칙칙·비네팅 …)에 있으면 상한·하한·해제·강도 클램프를 걸고, 그냥 룩이면
  ("부드럽게 말고") 그 룩의 반대 델타를 0.6배로 적용합니다. 상한·하한은 모든 룩을 적용한 뒤
  마지막에 검사하므로, 같은 문장 앞쪽의 "확 화려하게"가 상한을 뚫지 못합니다.
- 강도는 의도 바로 앞 12자 안의 수식어로 결정하고, 같은 룩이 두 번 나오면 한 번만 적용합니다.
- 매칭이 0건이면 곧바로 로컬 LLM 추론 경로로 넘깁니다. 남은 문장(`unmatched`)이 두 낱말 이상이거나
  세 글자 이상이면 로컬 LLM이 그 부분만 이어서 해석합니다(알아들은 문장을 다시 해석하지 않도록).
- 적용 뒤에는 `core/EditNarrator.kt`가 **실제 전/후 레시피 차이**로 "채도를 18% 올리고 …" 문장을 만들어
  입력창 위 카드에 보여 줍니다. 말이 아니라 값에서 나오므로 프리뷰와 항상 일치합니다.

`nl/SceneAnalyzer.kt`는 밝기 분포·채도·색 편향·클리핑·디테일을 측정하고,
`nl/AestheticPlanner.kt`가 "예쁘게/작품처럼/…" 요청에 그 사진에 맞는 양을 더합니다.

## 5. 로컬 LLM

- `llm/LlmModels.kt` — Hugging Face의 공개 `.task` 번들(Qwen2.5 0.5B/1.5B q8). 계정·키 불필요.
- `llm/LlmModelStore.kt` — `.part` 파일로 내려받고 크기 검증 후 이름 변경, 진행률 콜백.
- `llm/LocalLlmEngine.kt` — MediaPipe `LlmInference`(maxTokens 512, greedy). 로딩은 Mutex로 한 번만.
- `llm/LlmRecipeDecoder.kt` — 코드펜스·잡설이 섞인 답에서 첫 `{…}`를 균형 있게 뽑아 파싱,
  허용 키만 남기고 `LlmScale`로 슬라이더 단위로 환산, 범위는 레시피에서 다시 클램프.
  잘린 JSON은 괄호를 닫아 복구하고, 작은따옴표·따옴표 없는 키·끝 쉼표·숫자 문자열·퍼센트·
  한국어 파라미터 이름·중첩 그룹·새어 나온 `<|im_start|>` 토큰까지 받아 줍니다.
- 프롬프트에는 채팅 템플릿 토큰을 넣지 않습니다. MediaPipe `.task` 번들이 Qwen 템플릿을 내부에서
  입히므로, 넣으면 두 번 적용되어 모델이 JSON 대신 특수 토큰을 뱉습니다.
- 프롬프트에는 말버릇 무시·부정·억제·상반된 요구 규칙과 `샤하게`/`꾸안꾸`/`느좋` 예시가 들어가고,
  요청 문장은 `NaturalLanguageParser.salient`로 말버릇을 덜어 낸 뒤 들어갑니다.

## 6. LUT

`data/`의 Lorenzo 디코더와 카탈로그는 이전 FilmCam 구현을 그대로 가져왔습니다.
`lut_residuals.bin`(206KB)을 풀어 17³×3 바이트 LUT 57개를 만들고, 선택한 것만 3D 텍스처로 올립니다.
