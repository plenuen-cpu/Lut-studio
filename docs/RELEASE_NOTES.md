# Lumen 2.2.5 · 세로 비교선 + 보정 패널을 열어도 사진이 커진 화면

실사용 중 두 가지를 요청하셨습니다.

> "슬라이드 하면 작업 사진 영역이 너무 작아지고?"
> "비교 슬라이드는 이미지에 세로로 그어져야 할 것 같아."

둘 다 반영했습니다.

## 1. 슬라이더/LUT 패널을 열어도 작업 사진이 큼직하게

### 무엇이 문제였나

`EditorScreen.kt`의 `SliderPanel`이 **고정 300dp**였고, 그 안에 8개 그룹의 머리글과 슬라이더를 모두
한 `LazyColumn`에 쌓아 두었습니다. 아래 위젯이 위에서부터 차례로 자리를 잡고 사진 프리뷰만
`weight(1f)`로 남는 폭을 받기 때문에, 패널을 열면 사진이 그만큼 쪼그라들었습니다.

```
사진 프리뷰 (weight 1f)        ← 패널 300dp + 도구 줄 + 입력창 + 히스토리 + 내레이션 카드가
                                 먼저 자리를 잡고 남은 높이만 받았다
보정 히스토리 칩 줄
빠른 요청 줄
보정 내역 카드
입력창
하단 도구 줄 (52dp)
슬라이더 패널 (300dp 고정)
```

### 어떻게 고쳤나

- **패널 최대 높이 176dp** (`SLIDER_PANEL_MAX_HEIGHT`, `Modifier.heightIn(max = ...)`). 고정 300dp가
  아니라 사진이 남는 만큼만 씁니다.
- **한 줄 카테고리 칩** — 8개 그룹 머리글을 모두 그리지 않고, 칩 한 줄(약 32dp)에서 그룹을 고르면
  **그 그룹의 슬라이더만** 펼칩니다. 내용은 패널 안에서 위아래로 스크롤됩니다. 칩 이름은 짧게
  (톤 · 색감 · 디테일 · 구도 · 강조 · 영역 · HSL · 룩) — `ParamGroup`에 `chip` 이름을 추가했습니다.
- **얇은 슬라이더 행** — 라벨/값 글자를 11sp·10sp로 줄이고, 슬라이더 높이 22dp → 20dp, 행 패딩 제거.
- **패널이 열린 동안 히스토리 줄을 접습니다.** 보정 칩 줄과 안내 문구는 패널을 닫으면 다시 나옵니다.
- **보정 내역 카드는 한 줄 모드**로 접힙니다(캡션 숨김, 1줄, 작은 × 버튼). 패널을 만지는 동안에도
  "무엇이 바뀌었는지"는 한 줄로 계속 보입니다.
- **필름 룩 줄도 최소 높이로** — 머리글·칩 줄·강도 슬라이더의 패딩과 글자를 줄였습니다.
- **두 패널은 동시에 열리지 않습니다.** 슬라이더를 열면 룩 줄이 닫히고, 룩을 열면 슬라이더가 닫힙니다.
  둘이 같이 서면 사진이 다시 작아지기 때문입니다.

결과: 패널을 열어도 사진이 차지하는 높이가 대략 **200dp → 400dp 안팎**으로 늘어납니다(360×800dp 화면
기준). 정확한 픽셀은 실기기에서 확인이 필요합니다.

## 2. 비교선은 세로로 (왼쪽 = 원본, 오른쪽 = 보정)

- 셰이더(`gl/ShaderSource.kt`): `uSplitY`(가로) → **`uSplitX`**. 마지막 단계가
  `c = mix(original, c, step(uSplitX, vUv.x))` — **선 왼쪽은 원본, 오른쪽은 보정 결과** 픽셀입니다.
- 좌표계 정합성: GL 뷰포트를 사진이 들어앉는 사각형(`fit()`)에 정확히 맞춰 그리고 있어서 `vUv.x`는
  곧 사진 왼쪽부터의 비율입니다. 화면 오버레이도 **같은 aspect-fit 식으로 사진 사각형(좌·상·폭·높이)을
  계산**해 선을 그 사각형 안에 놓으므로, 레터박스가 있는 사진에서도 선과 실제 경계가 어긋나지 않습니다.
- 오버레이(`ui/EditorScreen.kt`): 세로선 + 중앙 핸들(↔) + 사진 사각형의 **좌·우 상단 `원본`/`보정`
  배지**. 드래그는 `detectHorizontalDragGestures`로 좌우이며, 이동량을 **사진 폭으로 나눠** 0f..1f
  비율로 넘깁니다(셰이더와 같은 축). 위쪽에 `마스크 보기`·`세로 비교` 칩이 있는 자리와 겹치지 않게
  배지는 한 줄 아래에 놓습니다.
- 상태 이름도 `splitY` → `splitX`로 정리했습니다(`EditorViewModel.UiState`, `RenderSpec`, 유니폼).
  저장 경로(`OffscreenExporter`)는 그대로 `splitEnabled = false`라 **저장 파일에는 선이 들어가지
  않습니다.**
- 프리뷰 오른쪽 위 칩 라벨: `가로 비교` → **`세로 비교`**.

## 검증

- `glslangValidator`(ESSL 3.00) — vertex/fragment **0 error**.
- 단위 테스트 **161개 전부 통과** (2.2.4의 154 + 신규 7):
  - `SplitCompareTest` 5개: 셰이더가 `step(uSplitX, vUv.x)`로 x축을 자르는지, `uSplitX`가 프로그램에
    등록·바인딩되는지, `RenderSpec`·`UiState`에 `splitX`만 있고 `splitY` 잔재가 없는지, 오버레이가
    좌우 드래그이며 이동량을 사진 폭으로 나누는지, 내보내기가 분할선을 끄는지.
  - `EditorLayoutTest` 2개: 슬라이더 패널이 고정 300dp로 돌아가지 않고 최대 높이가 150~190dp인지,
    히스토리 줄이 패널 열림에 접히고 보정 내역 카드가 한 줄 모드인지.
- `versionCode 225` / `versionName 2.2.5`, `apksigner verify` → **APK Signature Scheme v2 통과**
  (서명 인증서 SHA-256 `d3243f19…`, 2.2.4와 동일 → **삭제 없이 덮어 설치**).
- APK 62,292,327 bytes (배포 한도 66MB 내). dex에 `세로 비교`·`uSplitX`가 들어 있고 `uSplitY`는
  없는 것을 확인했습니다.

## 남은 확인

1. 폰에서 `슬라이더`를 열었을 때 **사진이 예전보다 확실히 커졌는지**. 패널 위쪽 칩(톤·색감·디테일·구도·
   강조·영역·HSL·룩)으로 그룹을 바꿔 보고, 그룹 내용이 패널 안에서 스크롤되는지 봐 주세요.
2. `세로 비교`를 켜고 선을 좌우로 끌었을 때 **선과 원본/보정 경계가 정확히 일치**하는지. 세로로 긴
   사진과 가로로 긴 사진 둘 다 보면 레터박스 좌표가 맞는지 확인됩니다.
3. 글씨 크기를 키운 설정에서 패널 칩과 슬라이더가 겹치지 않는지.

이 환경에는 에뮬레이터·GPU가 없어 **픽셀 렌더링은 확인하지 못했습니다.** 좌표 계산·배치·컴파일·테스트
·서명까지만 검증했습니다. 이상이 있으면 화면 캡처와 함께 알려 주세요.
