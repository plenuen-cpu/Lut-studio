# Lumen 2.2.3 · 로컬 LLM이 답한 직후 `PatternSyntaxException` (긴급 핫픽스)

v2.2.2에서 "로컬 LLM이 문장을 읽는 중…" 다음에 **"하던 작업을 끝내지 못했어요 … (오류를
기록해 두었어요: PatternSyntaxException)"** 카드가 뜨던 문제를 고쳤습니다. 2.2.2가 네이티브
크래시를 막아 모델이 처음으로 **답을 내놓기 시작**하자마자, 그 답을 읽는 코드에서 터진 것입니다.

## 무엇이 문제였나

`app/src/main/java/com/plenuen/lumen/llm/LlmRecipeDecoder.kt` **228번째 줄**:

```kotlin
return builder.toString().replace(Regex(",\\s*}"), "}")
```

정규식 `,\s*}` — **캐릭터 클래스 밖의 리터럴 `}`가 이스케이프되지 않았습니다.**

- **데스크톱 JVM**(`java.util.regex`)은 홀로 있는 `}`를 리터럴로 받아들입니다. 그래서 단위 테스트
  148개가 전부 통과했고, 로컬에서도 재현되지 않았습니다.
- **Android는 `Regex`를 ICU로 컴파일합니다**(libcore `NativeRegEx` → `uregex_open`). ICU에서
  이스케이프 없이 리터럴로 쓸 수 없는 문자 집합은 `regexst.cpp`의
  `gRuleSet_rule_chars = "*?+[(){}^$|\\."` 이고, `regexcst.txt`의 `term:` 상태는 이 집합에 든 문자를
  만나면 `doRuleError`(= `U_REGEX_RULE_SYNTAX`)로 끝납니다. 즉 `}`는 **문법 오류** →
  `java.util.regex.PatternSyntaxException`.

이 줄은 `closeBraces()` 안에 있고, `candidates()`가 모델 답에서 쉼표를 하나씩 잘라 가며 후보를
만들 때마다 호출됩니다. 그래서 **쉼표가 하나라도 든 LLM 답은 예외 없이 이 줄을 지납니다.**
`relax()`(정규식 4개)는 나머지 후보를 만들 때 지나가고, 그중 `{`·`}`를 쓰는 것은 이 한 줄뿐이었습니다.

- 도입 시점: 커밋 `8de92de`(v2.0.2). v2.2.1까지는 엔진이 상한 초과로 답을 내기 전에 프로세스가
  죽어서(2.2.2에서 수정) 이 줄에 도달한 적이 없었습니다. **2.2.2가 드러낸 잠복 버그**입니다.
- 브리프가 의심한 `Regex("\\{...\\}")` 형태의 JSON 추출 정규식은 코드에 없습니다. JSON 추출은
  이미 `indexOf('{')`와 깊이 세기로 되어 있습니다.

## 어떻게 고쳤나

1. **`closeBraces()`**: `Regex(",\s*}")` → `stripTrailingCommas()`. 따옴표 안/밖을 구분하는 문자
   스캔이라 **문자열 속 쉼표·중괄호는 건드리지 않습니다**(`"빈티지 {필름}, 차분하게"`가 살아남습니다).
2. **`relax()`**: 정규식 4개를 전부 없애고 한 번의 문자 스캔으로 바꿨습니다. 하는 일은 같습니다 —
   작은따옴표 문자열을 큰따옴표로, `{`·`,` 뒤의 따옴표 없는 키를 인용, 닫는 `}`·`]` 앞의 쉼표 제거.
   이제 **모델 답을 읽는 경로에는 정규식이 하나도 없습니다.**
3. **회귀 방지 테스트 5개 추가**(`RegexSafetyTest.kt`):
   - `IcuRegexAuditTest`: 앱 소스 전체를 훑어 **모든 `Regex(...)` 호출의 문자열 인자를 이어 붙여**
     ICU 규칙(이스케이프 안 된 `{`/`}` 금지, 닫히지 않은 그룹·클래스 금지)으로 검사하고, JVM
     파서로도 컴파일해 봅니다. 빈 검사가 되지 않도록 최소 4개 패턴을 찾았는지도 확인합니다.
   - 같은 클래스가 **`,\s*}`는 잡아내고, 고친 뒤의 패턴들은 통과**하는지 직접 고정합니다.
   - `MessyModelAnswerTest`: 깔끔한 JSON, 코드펜스, 앞뒤 잡설, 잘린 답, 남은 쉼표, 작은따옴표+맨 키,
     문자열 속 `{}`·쉼표·아포스트로피, 잘린 문자열, `{` 한 글자, 빈 답, 채팅 템플릿 토큰까지
     **어떤 모양에도 예외가 나지 않는지** 확인합니다.

## 검증

- 단위 테스트 **153개 전부 통과**(기존 148 + 신규 5).
- `versionCode 223` / `versionName 2.2.3`, `apksigner verify` → **APK Signature Scheme v2 통과**.

## 남은 확인

같은 문장을 한 번 더 보내 주세요. 이제 "읽는 중…" 다음에 **보정 카드**가 떠야 합니다. 로컬 LLM은
여전히 0.5B 모델이라 답이 어설플 수 있지만, **어떤 답이 와도 앱이 멈추지는 않습니다**. 그래도
카드가 뜨지 않으면 설정(⚙️) → "최근 오류 기록"의 마지막 줄을 그대로 보내 주세요.
