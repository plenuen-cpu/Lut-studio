# Lumen 2.3.0 — 진단하고, 조합으로 고르는 자연어 비파괴 사진 보정 (Android)

사진 한 장을 고르고 **"조금 더 따뜻하게, 부드럽게"** 처럼 말하면 그대로 보정되는 안드로이드 앱입니다.
원본 파일은 절대 건드리지 않고, 모든 보정은 `EditRecipe`라는 JSON 상태와 히스토리로만 관리합니다.
프리뷰와 원본 해상도 저장이 **같은 GLES 3.0 셰이더**를 쓰기 때문에 화면에서 본 그대로 파일이 나옵니다.

- 이전 저장소의 `FilmCam`(Lut-studio) 코드를 대체한 2.0 버전입니다.
- 화면에서 쓰던 **필름·카메라 3D LUT 57종**(Kodak 24, Fujifilm 14, Agfa 7, Ilford 1, Leica 6, Ricoh GR 5)은
  그대로 추출해 새 앱에 통합했습니다. LUT 바이트는 이전 빌드와 SHA-256 단위로 동일합니다(테스트로 고정).

최신 APK: <https://github.com/plenuen-cpu/Lut-studio/releases/latest>

이미 설치된 Lumen이 있으면 먼저 삭제하고 설치하세요. (패키지 이름이 `com.plenuen.filmcam`인
옛 FilmCam과는 별개 앱이라 함께 설치해도 됩니다.)

## 무엇이 들어 있나

### 1. 비파괴 편집
- 원본은 읽기 전용. `EditRecipe`(파라미터 30여 개) + 히스토리 스택만 바뀝니다.
- 되돌리기/다시 실행, 초기화, **화면을 길게 눌러 원본과 비교**, 슬라이더 수동 미세조정.
- 저장은 항상 **원본 해상도의 새 파일** → `Pictures/Lumen/Lumen_yyyyMMdd_HHmmss.jpg`.

### 1-1. 세로선 Before & After 비교
- 프리뷰 위에 얇은 **세로선** + 중앙 핸들(↔) + 좌·우 상단 `원본`/`보정` 배지를 그리고, 손가락으로
  **좌우로 끌어** 비교합니다(v2.2.5 — 이전에는 가로선을 위아래로 끌었습니다).
- 셰이더 유니폼 `uSplitEnabled`/`uSplitX`: **선 왼쪽은 원본, 오른쪽은 보정 결과** 픽셀
  (룩·그레인·비네팅 포함). 셰이더는 `vUv.x`를 `uSplitX`와 비교하고, GL 뷰포트가 사진이 들어앉는
  사각형과 정확히 같아서 화면 오버레이의 선 위치와 픽셀 경계가 어긋나지 않습니다 — 사진 비율이
  화면과 달라 레터박스가 생겨도 좌표계는 사진 폭 기준(0f..1f)으로 같습니다.
- 프리뷰 오른쪽 위 `세로 비교` 칩으로 원터치 토글. **저장 파일에는 선이 들어가지 않습니다.**

### 1-2. 보정 내역 메시지
- 적용할 때마다 `EditRecipe` 전/후를 비교해 실제로 바뀐 값만 문장으로 만듭니다(`core/EditNarrator.kt`).
  예: "채도를 18% 올리고, 하이라이트를 20% 낮추고, 색온도를 따뜻하게(25%) 했어요."
- 입력창 바로 위 반투명 카드에 표시되며, 슬라이더를 직접 움직여도 같은 방식으로 나옵니다.

### 1-3. 영역 마스킹 — 인물·배경·하늘만 따로 보정
- 앱을 열어 사진을 고르면 곧바로 **온디바이스 세그멘테이션 마스크**를 만듭니다.
  기본 경로는 MediaPipe **ImageSegmenter + `selfie_multiclass_256x256.tflite`**(6클래스: 배경·머리카락·
  피부·얼굴·옷·기타)이고, 배경(클래스 0)을 뺀 나머지를 피사체로 봅니다.
- 하늘은 모델이 아니라 **사진 자체**에서 찾습니다(색·밝기·위치·행 단위 비율). 피사체로 잡힌 픽셀은
  하늘에서 제외되고, 둘 다 **가우시안 페더링**(박스 블러 3회)되어 경계가 계단처럼 보이지 않습니다.
- 마스크는 GL 텍스처 한 장으로 올라갑니다: **R = 피사체, G = 하늘**, 배경은 셰이더가 `1 − R − G`로
  계산합니다. 프리뷰와 원본 해상도 저장이 **같은 생성기·같은 마스크**를 쓰므로 화면과 파일이 같습니다.
- 모델을 못 열거나 읽지 못하면 **색·위치 기반 폴백**(테두리 색과 다른 정도 + 중앙 가중치)으로
  물러나 영역 슬라이더가 계속 동작합니다. 슬라이더 패널의 `영역 보정` 탭에 어느 경로로 만들었는지
  표시됩니다.
- 영역 파라미터: 피사체(밝기·채도·색온도·선명도), 배경(밝기·채도·색온도·선명도·**흐림**),
  하늘(밝기·채도·색온도·**파랑**). `마스크 보기` 칩을 켜면 피사체는 주황, 하늘은 파랑으로 칠해집니다.

### 1-4. 8색 HSL 핀셋
- 빨강 · 주황 · 노랑 · 초록 · 청록 · 파랑 · 보라 · 자홍 8개 대역마다 **색조·채도·밝기** 24개 슬라이더.
- 셰이더는 픽셀을 HSL로 바꾼 뒤 **코사인 창**으로 대역을 겹쳐 섞고 다시 RGB로 돌립니다.
  각 대역은 자기 중심에서 1, 이웃 중심에서 0이라 이웃끼리 정확히 보완되고(가중치 합 = 1),
  색 경계가 뚝 끊기지 않습니다. 회색(채도 0.03 미만)은 건드리지 않습니다.
- 색조 노브는 ±30°까지 돌고, 채도는 배율, 밝기는 중간톤 위주로 움직입니다.
- `[색상별 HSL]` 탭에서 색 칩을 골라 세 슬라이더를 조절하고, 그 색만 초기화할 수 있습니다.
한 개의 프래그먼트 셰이더(`gl/ShaderSource.kt`)가 아래를 모두 실제로 계산합니다.

| 묶음 | 파라미터 |
| --- | --- |
| 기하 | 수평 맞춤(±15°), 수직 원근, 자동 내접 크롭 |
| 기본 톤 | 노출, 대비, 하이라이트, 섀도우, 화이트, 블랙, 페이드, **톤 곡선(섀도우·미드톤·하이라이트)** |
| 색감 | 색온도, 틴트, 활기, 채도, 색 정돈, 색 교차, 색 분리(섀도우/하이라이트 색상·균형), 피부톤 정리, 흑백 |
| 디테일·질감 | 명료도, 텍스처, 디헤이즈, 샤프닝, 글로우, 할레이션, 그레인, 비네팅 |
| 강조 | 피사체 강조(중심 분리 + 주변 누르기) |
| 영역 | 피사체·배경·하늘 밝기/채도/색온도/선명도, **피사체 대비·입체감·피부톤 보호**, 배경 흐림·**하이라이트 억제**, 하늘 파랑·**디테일** (마스크 가중·경계 인식) |
| 8색 HSL | 빨강·주황·노랑·초록·청록·파랑·보라·자홍 각각 색조/채도/밝기 |
| 룩 | 3D LUT 57종 + 룩 강도 |

### 2-1. ✨ 자동 보정 v2.3 — 사진을 먼저 읽고, 조합으로 고르고, 게이트로 거른다

v2.2.5의 자동 보정은 **슬라이더 하나씩** 올려 보고 NIMA 점수가 오르는 쪽만 남기는 방식이었습니다.
그래서 역광 인물(노출·하이라이트·피사체 마스크가 동시에 필요), 날아간 하늘(하이라이트만 내리면
나머지가 죽음), 야경(섀도우를 열면 노이즈) 같은 장면에서 답을 못 찾았고, NIMA가 대비·채도를
사람보다 좋아하다 보니 **하늘이 하얗게 타고 얼굴이 주황으로 가도 점수는 올라**갔습니다.

v2.3은 세 단계로 바뀌었습니다.

#### (1) 사진 진단 — `engine/PhotoDiagnosis.kt`
자동 보정 전에 사진 자체를 잽니다. 새 모델은 쓰지 않고, 이미 있던 `SceneAnalyzer`·히스토그램·
MediaPipe 마스크를 그대로 재사용합니다(완전 오프라인).

- 전체·피사체·배경·하늘의 노출(평균·p05·p50·p95), **하이라이트 클리핑 %**, **암부 손실 %**
- **화이트밸런스**(gray-world): 채널 편향과 색온도·틴트가 어느 쪽으로 얼마나 틀었는지
- 대비·명암 분포(동적 범위) — 납작함 / 과함
- **피부톤**(피사체 마스크 안의 피부 색조·채도·휘도와 자연 대역 18~40°·0.16~0.42에서의 이탈)
- **피사체-배경 분리**(밝기 차·대비 차)와 배경의 시선 분산 밝은 영역
- 색 균형·과포화 비율
- **장면 유형**: 인물 · 역광 인물 · 풍경 · 과노출 풍경 · 야경 · 실내 · 음식 · 저대비 · 색편향 · 일반
  (피사체 마스크의 **모양**까지 봅니다 — 접시나 가구는 마스크에 잡혀도 사람이 아닙니다)
- 결과는 "역광 인물 · 피사체가 배경에 묻힘, 하이라이트 날아감"처럼 카드 첫 줄에 그대로 나옵니다.

#### (2) 다변수 Coarse-to-Fine 탐색 — `engine/RecipeSearch.kt`
- 진단이 **장면별 후보 레시피 3~4개**를 만듭니다(`engine/SceneStrategy.kt`). 인물은 피사체 밝기·
  피부톤 보호·배경 눌러 주기, 야경은 암부 상한을 낮춰 노이즈를 막고, 과노출 풍경은 하늘·화이트를
  함께 내리는 식입니다. 노출·대비·하이라이트·섀도우·색온도·틴트·채도·활기·명료도·영역·톤 커브·
  배경 하이라이트·하늘 디테일을 **한 후보 안에서 동시에** 조합합니다.
- ① 거친 단계: 12~18개 후보를 모두 그려 평가 → ② 유망 후보 3개를 골라 두 단계 크기로 좌표 다듬기
  → ③ 상위 두 후보의 절충안까지 한 번 더.
- **예산 제어**: 평가 횟수 상한(기본 72)과 **실행 시간 상한(기본 6초)** 을 동시에 지킵니다. S25 울트라
  에서 2~4초대에 끝나고, 느린 기기에서는 시간이 되면 거기서 멈추고 지금까지의 최선을 씁니다.
- 룩 선택·수평·수직·HSL 핀셋은 후보 생성 자체에서 제외됩니다(사용자 것이므로).

#### (3) 다중 품질 평가 + 하드 탈락 — `engine/QualityEvaluator.kt`
점수를 NIMA 하나에 맡기지 않습니다. 후보마다 일곱 가지를 보고, **점수를 비교하기 전에** 사진을
망가뜨린 후보를 먼저 버립니다.

| 항목 | 무엇을 보나 |
| --- | --- |
| NIMA | 미적 점수(다른 항목과 함께 가중 0.34) |
| 클리핑 | 하이라이트 날아감·암부 뭉개짐의 절대량과 **원본 대비 증가분** |
| 색 | 평균 채도 폭주, 과포화 픽셀 비율, 색 균형 이동 |
| 피부 | 피부 색조 이탈(°), 채도 증가, 휘도 변화 |
| 분리 | 피사체-배경 밝기·대비 차가 원본보다 벌어졌는지 |
| 장면 적합 | 그 장면이 기대하는 방향(인물=얼굴 들기, 풍경=하늘 내리기, 야경=암부 조심…) |
| 과보정 | 레시피 이동량(가드레일 대비) + 평균 픽셀 변화 |

**하드 탈락 게이트**: 하이라이트가 2%p 넘게 늘거나, 암부가 3%p 넘게 뭉개지거나, 피부 색조가 11°
넘게 돌거나, 채도가 1.32배를 넘거나, 평균 픽셀이 0.20 넘게 바뀌면 **NIMA가 높아도 탈락**입니다.
NIMA가 0.02 낮아도 하늘이 살아 있고 얼굴이 사람인 쪽이 이깁니다.

- 결과 카드: `역광 인물 · 피사체가 배경에 묻힘. NIMA 4.09 → 4.17 (+0.08), 피사체 밝기 +14%, …`
  (걸러 낸 후보 수와 품질 점수 변화도 함께)

#### (4) 자연어와 진단의 결합 — `engine/ScenePlanner.kt`
- 같은 **"고급스럽게"** 도 인물에서는 피부톤 보호와 피사체 입체감이 붙고, 야경에서는 하이라이트 톤
  억제가 붙습니다. **"선명하게"** 는 저대비 사진에서 명료도를 더 올리고, 야경에서는 노이즈를 고려해
  덜 올립니다. 이미 따뜻한 사진에 "따뜻하게"는 폭을 줄입니다.
- 규칙 파서의 확신도가 **문장을 실제로 읽은 비율**로 계산됩니다(v2.2.5는 한 낱말만 걸려도 0.95~0.98
  고정). 복합·모호한 문장은 확신도가 0.75 아래로 떨어져 **남은 부분이 로컬 LLM으로 넘어가고**, 그
  프롬프트에는 진단 요약("역광 인물, 하이라이트 3% 날아감, 피부톤 정상")이 함께 들어갑니다.

### 2-1-1. 30장 이상 합성 장면 비교 검증
실사진을 저장소에 넣을 수 없으므로, **프로그래밍으로 만든 36장**(인물·역광 인물·풍경·과노출 풍경·
야경·실내·음식·저대비·색편향 × 4변형)으로 v2.2.5와 v2.3을 같은 조건에서 비교합니다
(`app/src/test/.../EngineBenchmarkTest.kt`, 렌더는 셰이더 산술을 옮긴 `CpuPipeline`, 점수는
`ProxyAesthetic`). 측정은 두 엔진이 끝난 뒤 별도 코드로만 합니다.

| 지표(36장 평균) | v2.2.5 | v2.3 |
| --- | --- | --- |
| 하이라이트 클리핑 | 0.12% | **0.04%** |
| 피사체-배경 분리 | −0.041 | **−0.006** |
| 평균 픽셀 변화(과보정) | 0.022 | 0.035 |
| 품질 종합 점수 | 0.747 | **0.764** |
| 피부 이탈(게이트 문턱 1.0) | 0.01 | 0.09 (최대 0.24) |

그리고 **실제 NIMA 모델**(`nima_aesthetic.tflite`)로 같은 레시피를 다시 그려 채점한 교차 검증

36장 중 20장에서 v2.3이 더 높았습니다. 두 수치 모두 **합성 장면·CPU 파이프라인** 기준이며, 실사진과
기기 GPU에서의 최종 확인은 별도입니다(아래 "실기기에서 확인해야 하는 것").

### 2-2. 누르면 지워지는 히스토리
- 히스토리는 사진 스냅샷 더미가 아니라 **순서 있는 단계 목록**(`List<EditStep>`)입니다. 각 단계는 자기가
  바꾼 것만 들고 있습니다 — 말로 한 보정은 델타를, 룩·슬라이더·자동은 그때 정한 절대값을.
- 그래서 **가운데 단계만 뺄 수 있습니다**: 1번 "따뜻하게" · 2번 "필름처럼" · 3번 "수평"에서 2번 칩을
  누르면 1·3번은 그대로인 채 2번만 빠지고, 레시피가 원본부터 다시 합산되어 프리뷰에 바로 반영됩니다.
- 맨 아래 `원본` 칩은 지워지지 않습니다. 잘못 지웠으면 상단 **← 되돌리기**로 되살아납니다.
  (지우기·초기화·절반·되돌리기 모두 되돌릴 수 있는 스냅샷으로 남습니다.)

### 3. 자동 수평·수직
- **구조 텐서(structure tensor) 투표**로 기울기를 추정합니다: 640px 이하로 줄인 휘도 → 3×3 가우시안 →
  중심 차분 기울기 → 12px 블록마다 기울기 2차 모멘트 → ±45°로 접은 뒤 0.1° 히스토그램 → 피크 보간.
- 수평(0°)과 수직(90°)이 같은 축에 투표하므로 **수평·수직이 한 번에** 맞습니다.
- 회전 각도에 맞춰 `cropScale = max(cosθ + sinθ/a, cosθ + a·sinθ)`만큼 화면을 확대해
  **검은 테두리(빈 코너)가 생기지 않습니다**. 프리뷰와 원본 해상도 저장 모두 같은 UV 변환을 씁니다.
- 원터치 **[자동 수평·수직]** 버튼, 수동 각도 슬라이더(0.1° 단위), "수직 원근" 슬라이더 제공.

## 실기기에서 확인해야 하는 것

정적 빌드·단위 테스트·서명 검증까지는 이 환경에서 끝냈지만, **GL 렌더링과 로컬 LLM은 실제 GPU·NPU가
필요해 여기서 실행해 볼 수 없습니다.** 설치 후 아래를 확인하세요.

1. 갤러리 사진이 프리뷰에 뜨고 슬라이더/문장 보정이 즉시 반영되는지 (GLES 3.0 + 3D 텍스처)
2. [자동 수평·수직]이 기운 사진을 곧게 세우고 검은 코너가 생기지 않는지
3. [저장] 후 `Pictures/Lumen`의 파일이 화면과 같은지(원본 해상도)
4. 설정에서 모델(547MB)을 내려받고, 규칙이 모르는 문장이 LLM으로 해석되는지
5. 아주 큰 사진에서 저장 시 자동 축소 안내가 뜨는지 (긴 변 7000px까지는 원본 해상도로 저장하고,
   그보다 큰 사진은 메모리 보호를 위해 7000px로 줄이며 화면에 그 사실을 알립니다.)
6. 사진을 열었을 때 `영역 보정` 탭에 `마스크: MediaPipe selfie_multiclass · 인물 분리`가 뜨는지
   (= 모델이 실제로 돌았는지). 폴백이면 `색·위치 기반 폴백`으로 표시됩니다.
7. `마스크 보기`를 켜서 인물이 주황, 하늘이 파랑으로 칠해지는지 / "인물만 화사하게"가 인물에만 걸리는지
8. 8색 HSL에서 빨강 채도를 올렸을 때 빨간 사물만 진해지고 초록·회색은 그대로인지
9. **하단 줄 오른쪽의 [새 사진]·[저장]이 화면 폭과 상관없이 잘리지 않고 보이는지**(왼쪽 보정 도구는
   옆으로 밀어서 쓰는지), 버튼 글자가 커진 설정(큰 글씨)에서도 두 버튼이 겹치지 않는지
10. `슬라이더`를 열었을 때 **사진 영역이 예전보다 확실히 커졌는지**, 패널은 화면 아래 170여 dp만
    차지하고 그룹 칩(톤·색감·디테일·구도·강조·영역·HSL·룩)을 눌러 그룹을 바꿀 수 있는지.
    그룹 내용은 패널 안에서 위아래로 스크롤됩니다.
11. `세로 비교`를 켜고 선을 좌우로 끌었을 때 **선 위치와 원본/보정 경계가 정확히 일치**하는지
    (특히 세로로 긴 사진·가로로 긴 사진에서), 선 왼쪽이 원본·오른쪽이 보정인지
12. `✨ 자동`이 **2~4초 안에** 끝나고, 결과 카드 첫 줄에 진단("역광 인물 · …")이 뜨는지.
    야경 사진에서 암부가 새까맣게 뭉개지지 않는지, 인물 사진에서 얼굴색이 주황으로 가지 않는지
13. 영역 슬라이더의 새 항목(피사체 대비·입체감·피부톤 보호, 배경 하이라이트, 하늘 디테일)이
    실제로 그 영역에만 걸리는지. **마스크 경계에 하얀 테두리(후광)나 색 번짐이 생기지 않는지**
    (경계 인식 블렌딩이 기기 GPU에서 의도대로 도는지 — 여기서는 확인할 수 없는 부분입니다)
14. 톤 곡선 3종(섀도우·미드톤·하이라이트)을 올렸을 때 이미 밝은 하늘은 덜 움직이고 중간톤이
    먼저 밝아지는지
15. "고급스럽게"를 인물 사진과 야경 사진에서 각각 말했을 때 **카드에 적히는 보정 항목이 다른지**,
    로컬 LLM 답변에 사진 상태(장면·클리핑·피부)가 반영되는지
