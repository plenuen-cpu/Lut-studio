# Lumen 2.2.3 — 자연어 비파괴 사진 보정 (Android)

사진 한 장을 고르고 **"조금 더 따뜻하게, 부드럽게"** 처럼 말하면 그대로 보정되는 안드로이드 앱입니다.
원본 파일은 절대 건드리지 않고, 모든 보정은 `EditRecipe`라는 JSON 상태와 히스토리로만 관리합니다.
프리뷰와 원본 해상도 저장이 **같은 GLES 3.0 셰이더**를 쓰기 때문에 화면에서 본 그대로 파일이 나옵니다.

- 이전 저장소의 `FilmCam`(Lut-studio) 코드를 대체한 2.0 버전입니다.
- 화면에서 쓰던 **필름·카메라 3D LUT 57종**(Kodak 24, Fujifilm 14, Agfa 7, Ilford 1, Leica 6, Ricoh GR 5)은
  그대로 추출해 새 앱에 통합했습니다. LUT 바이트는 이전 빌드와 SHA-256 단위로 동일합니다(테스트로 고정).

## 받기

최신 APK: <https://github.com/plenuen-cpu/Lut-studio/releases/latest>

- `Lumen-2.2.3.apk` — release 빌드(디버그 키로 서명, 바로 설치 가능)

온디바이스 인물 분리 모델(16MB)과 NIMA 미적 평가 모델(6.4MB), MediaPipe Vision·TensorFlow Lite
라이브러리가 APK에 함께 들어 있습니다. 사진은 물론 모델 추론도 네트워크를 쓰지 않습니다.
(debug 빌드는 저장소 릴리스에 올리지 않았습니다 — `gradle :app:assembleDebug`로 만들 수 있습니다.)

설치 후 갤러리에서 사진을 고르면 됩니다. 서명 키가 빌드마다 같지 않을 수 있으므로,
이미 설치된 Lumen이 있으면 먼저 삭제하고 설치하세요. (패키지 이름이 `com.plenuen.filmcam`인
옛 FilmCam과는 별개 앱이라 함께 설치해도 됩니다.)

## 무엇이 들어 있나

### 1. 비파괴 편집
- 원본은 읽기 전용. `EditRecipe`(파라미터 30여 개) + 히스토리 스택만 바뀝니다.
- 되돌리기/다시 실행, 초기화, **화면을 길게 눌러 원본과 비교**, 슬라이더 수동 미세조정.
- 저장은 항상 **원본 해상도의 새 파일** → `Pictures/Lumen/Lumen_yyyyMMdd_HHmmss.jpg`.

### 1-1. 가로선 Before & After 비교
- 프리뷰 위에 얇은 가로선 + 중앙 핸들 + `BEFORE`/`AFTER` 뱃지를 그리고, 손가락으로 위아래로 끌어 비교합니다.
- 셰이더 유니폼 `uSplitEnabled`/`uSplitY`: **선 위는 보정 전, 아래는 보정 후** 픽셀(룩·그레인·비네팅 포함).
- 프리뷰 오른쪽 위 `가로 비교` 칩으로 원터치 토글. **저장 파일에는 선이 들어가지 않습니다.**

### 1-2. 보정 내역 메시지
- 적용할 때마다 `EditRecipe` 전/후를 비교해 실제로 바뀐 값만 문장으로 만듭니다(`core/EditNarrator.kt`).
  예: "채도를 18% 올리고, 하이라이트를 20% 낮추고, 색온도를 따뜻하게(25%) 했어요."
- 입력창 바로 위 반투명 카드에 표시되며, 슬라이더를 직접 움직여도 같은 방식으로 나옵니다.

### 1-3. 영역 마스킹 — 인물·배경·하늘만 따로 보정
- 앱을 열어 사진을 고르면 곧바로 **온디바이스 세그멘테이션 마스크**를 만듭니다.
  기본 경로는 MediaPipe **ImageSegmenter + `selfie_multiclass_256x256.tflite`**(6클래스: 배경·머리카락·
  피부·얼굴·옷·기타)이고, 배경(클래스 0)을 뺀 나머지를 피사체로 봅니다.
- 하늘은 모델이 아니라 **사진 자체**에서 찾습니다(색·밝기·위치·행 단위 비율). 피사체로 잡힌 픽셀은
  하늘에서 제외되고, 둘 다 **가우시안 페더링**(박스 블러 3회)되어 경계가 계단처럼 보이지 않습니다.
- 마스크는 GL 텍스처 한 장으로 올라갑니다: **R = 피사체, G = 하늘**, 배경은 셰이더가 `1 − R − G`로
  계산합니다. 프리뷰와 원본 해상도 저장이 **같은 생성기·같은 마스크**를 쓰므로 화면과 파일이 같습니다.
- 모델을 못 열거나 읽지 못하면 **색·위치 기반 폴백**(테두리 색과 다른 정도 + 중앙 가중치)으로
  물러나 영역 슬라이더가 계속 동작합니다. 슬라이더 패널의 `영역 보정` 탭에 어느 경로로 만들었는지
  표시됩니다.
- 영역 파라미터: 피사체(밝기·채도·색온도·선명도), 배경(밝기·채도·색온도·선명도·**흐림**),
  하늘(밝기·채도·색온도·**파랑**). `마스크 보기` 칩을 켜면 피사체는 주황, 하늘은 파랑으로 칠해집니다.

### 1-4. 8색 HSL 핀셋
- 빨강 · 주황 · 노랑 · 초록 · 청록 · 파랑 · 보라 · 자홍 8개 대역마다 **색조·채도·밝기** 24개 슬라이더.
- 셰이더는 픽셀을 HSL로 바꾼 뒤 **코사인 창**으로 대역을 겹쳐 섞고 다시 RGB로 돌립니다.
  각 대역은 자기 중심에서 1, 이웃 중심에서 0이라 이웃끼리 정확히 보완되고(가중치 합 = 1),
  색 경계가 뚝 끊기지 않습니다. 회색(채도 0.03 미만)은 건드리지 않습니다.
- 색조 노브는 ±30°까지 돌고, 채도는 배율, 밝기는 중간톤 위주로 움직입니다.
- `[색상별 HSL]` 탭에서 색 칩을 골라 세 슬라이더를 조절하고, 그 색만 초기화할 수 있습니다.
한 개의 프래그먼트 셰이더(`gl/ShaderSource.kt`)가 아래를 모두 실제로 계산합니다.

| 묶음 | 파라미터 |
| --- | --- |
| 기하 | 수평 맞춤(±15°), 수직 원근, 자동 내접 크롭 |
| 기본 톤 | 노출, 대비, 하이라이트, 섀도우, 화이트, 블랙, 페이드 |
| 색감 | 색온도, 틴트, 활기, 채도, 색 정돈, 색 교차, 색 분리(섀도우/하이라이트 색상·균형), 피부톤 정리, 흑백 |
| 디테일·질감 | 명료도, 텍스처, 디헤이즈, 샤프닝, 글로우, 할레이션, 그레인, 비네팅 |
| 강조 | 피사체 강조(중심 분리 + 주변 누르기) |
| 영역 | 피사체·배경·하늘 밝기/채도/색온도/선명도, 배경 흐림, 하늘 파랑 (마스크 가중) |
| 8색 HSL | 빨강·주황·노랑·초록·청록·파랑·보라·자홍 각각 색조/채도/밝기 |
| 룩 | 3D LUT 57종 + 룩 강도 |

### 2-1. NIMA 자동 보정 — 점수를 실제로 재면서 고른다
- **온디바이스 NIMA**: `nima_aesthetic.tflite`(AVA 학습, 6.4MB)를 TensorFlow Lite로 기기 CPU에서 돌립니다.
  입력 224×224 · `[-1, 1]` 정규화, 점수는 1~10 확률분포의 가중평균. FrameCritic(앱·웹)과 같은 모델·전처리·
  계산이라 같은 사진은 같은 점수가 나옵니다. 상단 정보 줄에 `4032×3024 · NIMA 5.12`처럼 늘 떠 있습니다.
- **`[✨ 자동]` 버튼**: ① 기운 사진은 수평·수직부터 바로 세우고 ② 후보 레시피를 224×224 오프스크린에
  **프리뷰와 같은 셰이더**로 그려 그 픽셀을 NIMA에 넣어 채점합니다. 노출·대비·하이라이트·섀도우·화이트·
  블랙·활기·채도·명료도·색온도·텍스처·비네팅을 양방향으로 훑고(24후보), 가장 좋은 곳에서 더 작은 걸음으로
  두 번 더 다듬습니다(총 60후보 이내, 보통 2~4초).
- **가드레일**(`nima/NimaOptimizer.kt`의 `NimaGuardrails`): 모델은 채도·대비를 사람보다 조금 더 좋아합니다.
  그래서 파라미터마다 처음 값에서 움직일 수 있는 한도를 두고(노출 ±0.55EV, 대비 ±0.35, 채도 ±0.22,
  색온도 ±0.16 등), 룩 선택·수평·영역 마스크·HSL 핀셋은 **아예 건드리지 않습니다**. 한 라운드가 0.02점도
  못 올리면 손대지 않고 "이미 좋다"고 알려 줍니다.
- 결과 카드: `NIMA 미적 점수 4.85 → 5.38 (+0.53)로 자동 보정했어요. 노출 +0.12 EV, 대비 +9%를 조정했어요.`
- 모델을 못 열면 사진 통계 기반 규칙(예쁘게)으로 물러나고 그 사실을 카드에 적습니다. 사진은 어디로도
  나가지 않습니다.

### 2-2. 누르면 지워지는 히스토리
- 히스토리는 사진 스냅샷 더미가 아니라 **순서 있는 단계 목록**(`List<EditStep>`)입니다. 각 단계는 자기가
  바꾼 것만 들고 있습니다 — 말로 한 보정은 델타를, 룩·슬라이더·자동은 그때 정한 절대값을.
- 그래서 **가운데 단계만 뺄 수 있습니다**: 1번 "따뜻하게" · 2번 "필름처럼" · 3번 "수평"에서 2번 칩을
  누르면 1·3번은 그대로인 채 2번만 빠지고, 레시피가 원본부터 다시 합산되어 프리뷰에 바로 반영됩니다.
- 맨 아래 `원본` 칩은 지워지지 않습니다. 잘못 지웠으면 상단 **← 되돌리기**로 되살아납니다.
  (지우기·초기화·절반·되돌리기 모두 되돌릴 수 있는 스냅샷으로 남습니다.)

### 3. 자동 수평·수직
- **구조 텐서(structure tensor) 투표**로 기울기를 추정합니다: 640px 이하로 줄인 휘도 → 3×3 가우시안 →
  중심 차분 기울기 → 12px 블록마다 기울기 2차 모멘트 → ±45°로 접은 뒤 0.1° 히스토그램 → 피크 보간.
- 수평(0°)과 수직(90°)이 같은 축에 투표하므로 **수평·수직이 한 번에** 맞습니다.
- 회전 각도에 맞춰 `cropScale = max(cosθ + sinθ/a, cosθ + a·sinθ)`만큼 화면을 확대해
  **검은 테두리(빈 코너)가 생기지 않습니다**. 프리뷰와 원본 해상도 저장 모두 같은 UV 변환을 씁니다.
- 원터치 **[자동 수평·수직]** 버튼, 수동 각도 슬라이더(0.1° 단위), "수직 원근" 슬라이더 제공.

   - 연속 대화: "더 따뜻하게", "덜", "절반만", "취소/되돌리기", "다시 실행", "초기화"
   - 수평·수직: "수평 맞춰줘", "수직 수평 맞춰줘", "기울기 잡아줘", "반듯하게", "똑바로", "왼쪽으로 3도"
   - 룩 이름: "포트라 400", "벨비아", "라이카 모노" … → 57종 라이브러리에서 찾아 적용
2. **로컬 LLM** — 파서가 이해하지 못한 문장(또는 남은 부분)만 온디바이스 모델이 JSON으로 해석합니다.
   - 모델: **Qwen2.5-0.5B-Instruct (q8, 547MB)** 기본 / Qwen2.5-1.5B-Instruct (q8, 1.6GB) 선택
   - 런타임: MediaPipe **LLM Inference API**(`com.google.mediapipe:tasks-genai`, NDK 빌드 불필요)
   - 배포: APK에 넣지 않고 **첫 사용 시 진행률과 함께 Hugging Face에서 다운로드** → 앱 전용 저장소
   - 디코딩은 greedy(topK=1)로 고정해 같은 문장이 같은 결과를 내도록 했습니다.
   - 프롬프트는 **평문**입니다. `.task` 번들이 Qwen 채팅 템플릿을 안에서 입히므로 `<|im_start|>`를
     직접 넣으면 템플릿이 두 번 적용됩니다. 시스템 프롬프트에는 조절 가능한 모든 파라미터 이름,
     `-1.0~+1.0` 델타 범위, 대표 룩 예시, "사전에 없는 추상적 표현이라도 해석해 **파라미터 2개 이상**과
     한국어 `summary`를 내라"는 지침이 들어 있습니다.
   - 출력은 `{"label","summary","adjust":{...}}` 형태로 강제하고, 앱은 허용된 키만 받아
     범위를 다시 클램프합니다. 기하(회전)와 룩 번호는 모델이 건드릴 수 없습니다(룩은 이름으로만 제안).
   - 파서는 작은 모델의 지저분한 답을 받아 줍니다: 잘린 JSON의 괄호 닫기, 작은따옴표/따옴표 없는 키,
     숫자 문자열과 퍼센트, 한국어 파라미터 이름, 중첩 그룹, 새어 나온 특수 토큰 제거.
   - 모델이 없으면 "사전에 없는 표현이에요. 상단 설정(⚙️)에서 로컬 LLM(547MB)을 내려받으면…" 안내 카드와
     `설정` 바로가기를 띄웁니다.

### 5. 57종 3D LUT

- 사용자가 보낸 긴 구어체 문장이 상한·하한까지 지켜 한 번에 조화롭게 해석되는지
- 미적 평가가 사진 밝기에 따라 다른 보정을 내는지
- 레시피 클램프·누적·Set 블렌딩·JSON 왕복·히스토리(undo/redo/reset/half)

- 내접 크롭이 네 모서리를 원본 안에 유지하는지
- LUT 57종 SHA-256이 이전 빌드와 같은지
- 로컬 LLM JSON 파싱(코드펜스·잡설·미지의 키·범위 초과·잘린 JSON·숫자 문자열·한국어 키·중첩 그룹)
- 소스의 모든 `Regex(...)` 패턴이 **Android ICU 문법**을 지키는지(이스케이프 안 된 `{`/`}` 금지),
  그리고 어떤 모양의 모델 답(문자열 속 중괄호·쉼표, 잘린 문자열, 빈 답)에도 예외가 나지 않는지
- 보정 내역 문장이 실제 전/후 값에서 나오는지(단일/다중 항목, 룩 이름, 변화 없음)
- 가로 비교가 프리뷰 표시일 뿐 저장 기본값에는 들어가지 않는지
- 영역 지시 10가지가 그 영역 파라미터에만 걸리고 전체 노출·채도를 건드리지 않는지,
  "인물 사진" 같은 룩 이름을 가로채지 않는지, 부정문("하늘이 날아가지 않게")이 제한으로 남는지
- 8색 대역 가중치가 색상환 전체에서 합 1로 이어지고, 중심에서 1, 이웃에서 0인지,
  값이 0이면 픽셀이 그대로인지, 빨강 채도를 올려도 초록은 그대로인지
- 마스크 페더링이 경계를 번지게 하고 0/1 극단은 건드리지 않는지, 파란 위쪽 절반만 하늘로 읽는지,
  피사체 자리가 하늘에서 빠지는지, 폴백 피사체가 단색 사진에서 비어 있는지

## 실기기에서 확인해야 하는 것

정적 빌드·단위 테스트·서명 검증까지는 이 환경에서 끝냈지만, **GL 렌더링과 로컬 LLM은 실제 GPU·NPU가
필요해 여기서 실행해 볼 수 없습니다.** 설치 후 아래를 확인하세요.

1. 갤러리 사진이 프리뷰에 뜨고 슬라이더/문장 보정이 즉시 반영되는지 (GLES 3.0 + 3D 텍스처)
2. [자동 수평·수직]이 기운 사진을 곧게 세우고 검은 코너가 생기지 않는지
3. [저장] 후 `Pictures/Lumen`의 파일이 화면과 같은지(원본 해상도)
4. 설정에서 모델(547MB)을 내려받고, 규칙이 모르는 문장이 LLM으로 해석되는지
5. 아주 큰 사진에서 저장 시 자동 축소 안내가 뜨는지 (긴 변 7000px까지는 원본 해상도로 저장하고,
   그보다 큰 사진은 메모리 보호를 위해 7000px로 줄이며 화면에 그 사실을 알립니다.)
6. 사진을 열었을 때 `영역 보정` 탭에 `마스크: MediaPipe selfie_multiclass · 인물 분리`가 뜨는지
   (= 모델이 실제로 돌았는지). 폴백이면 `색·위치 기반 폴백`으로 표시됩니다.
7. `마스크 보기`를 켜서 인물이 주황, 하늘이 파랑으로 칠해지는지 / "인물만 화사하게"가 인물에만 걸리는지
8. 8색 HSL에서 빨강 채도를 올렸을 때 빨간 사물만 진해지고 초록·회색은 그대로인지
